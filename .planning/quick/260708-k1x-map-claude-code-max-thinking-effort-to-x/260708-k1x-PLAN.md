# Quick Task 260708-k1x: Map claude code max thinking effort to xhigh when calling OpenAI provider

## Problem

Claude Code client sends thinking effort `"max"` (its top effort level). When 9router routes to an OpenAI-format provider, `applyThinking()` in `open-sse/translator/concerns/thinkingUnified.js` case `"openai"` sets `body.reasoning_effort = level` verbatim. OpenAI's `reasoning_effort` enum does NOT include `"max"` (per `open-sse/providers/thinkingLevels.js` `L.openai = ["none","minimal","low","medium","high","xhigh"]` — caps at `xhigh`). Upstream returns HTTP 400 `"max effort not support"`.

## Root cause

`thinkingUnified.js:184-189` case `"openai"`:
```js
case "openai": {
  if (none && canDisable) { body.reasoning_effort = "none"; break; }
  const level = toLevel(eff);
  if (level) body.reasoning_effort = level;   // passes "max" straight through
  break;
}
```
`toLevel(eff)` returns `cfg.level` (= `"max"`) for level-mode configs. No clamp to the OpenAI-supported ceiling.

## Fix

Clamp `"max"` → `"xhigh"` in the openai case. `xhigh` is the highest level in `L.openai`. Other formats already clamp (`claude-adaptive` maps xhigh→high; `step` maps xhigh|max→high; `deepseek` maps xhigh|max→max). OpenAI case was the lone gap.
